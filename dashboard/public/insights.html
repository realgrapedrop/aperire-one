    Alert History Every alert, current and past, in one place. Live follows the last hour as it happens and refreshes itself; the time ranges (1h to 30d) show the history in that window. Whatever the range, anything firing right now is pinned to the top, so a long-running alert is never hidden by a short window. Severity chips narrow the tier; State is the lifecycle (Firing or Resolved). Ask Advisor investigates any row, and a A firing row also carries Ack and Mute 1h.     Configuration Current dashboard configuration loaded from disk. Read-only by design — all edits happen via SSH on the appropriate host, then a service reload. No write path through the browser, so a compromised dashboard process can't change rules or recipients. · read-only · edit on disk

    Rules Alert rules and thresholds. The full catalog lives in docs/METRICS-CATALOG.md. Two files: rules.yaml is the set this product ships and every update replaces it, and rules.local.yaml is yours, overriding a shipped rule by metric and severity, adding one, or switching one off. Reload reads both fresh, no restart needed. There is no web write path: edits route through SSH so a compromised dashboard process can't change alerting behavior.

    Relay Aperire-relay runs on the validator host (Box B) and ships metrics outbound to the dashboard. Outbound-only — zero inbound surface, nothing for the dashboard to push back. Restart (not reload) is required because the relay re-establishes its outbound connection on start. Multi-validator support is planned via RELAY_TOKENS on the dashboard end. See docs/RELAY-REFERENCE.md.
